1. VARIABLEN-MANAGEMENT
================================================================================

1.1 LOKALISIERUNG (CRITICAL!)
------------------------------

SCHLECHT - Globale Variable:
----------------------------
(defun c:MyCommand ()
  (setq pt1 (getpoint))
  ...
)

GUT - Lokale Variable:
---------------------
(defun c:MyCommand ( / pt1 pt2 height)  ; Nach "/" = lokal
  (setq pt1 (getpoint))
  ...
)

WARUM WICHTIG:
- Globale Variablen bleiben in AutoCAD aktiv
- Koennen andere Scripts stoeren
- Memory Leak vermeiden
- Alle Variablen landen im "atom list" von AutoCAD


1.2 MEMORY MANAGEMENT
---------------------

Variablen auf nil setzen wenn nicht mehr benoetigt:

(setq big-list nil)  ; Gibt Speicher frei

Jede Variable verbraucht Speicher. Gut fuer Performance bei grossen Datenmengen.


1.3 NAMING CONVENTIONS
----------------------

GUT - Sprechende Namen:
-----------------------
(setq insertion-point ...)
(setq scale-factor ...)
(setq *config-file* ...)  ; Globale mit *...*
(setq PT1 ...)            ; Grossbuchstaben fuer wichtige Werte

SCHLECHT:
--------

(setq a ...)

NIEMALS VERWENDEN:
-----------------
- PI, T, PAUSE (vordefiniert)

KONVENTIONEN:
- Symbole sind nicht case-sensitive
- Kapitalisierung hilft Lesbarkeit
- Verwende Bindestriche oder Unterstriche: my-var oder my_var


1.4 CONTEXT-NAMESPACE (VERPFLICHTEND!)
--------------------------------------

Jedes Script MUSS einen eindeutigen Namespace-Prefix verwenden.
Verhindert Kollisionen zwischen Scripts.

FORMAT:
-------
Prefix:funktionsname     (fuer interne Funktionen)
*Prefix:variable*        (fuer globale Variablen)

BEISPIELE AUS DEM PROJEKT:
--------------------------
LXI:   = LayerExportImport     (LXI:ensure-init, LXI:read-master)
LXP:   = LayerPlansatz         (LXP:ensure-assigned, LXP:get-sync-targets)
BGC:   = BgColor               (BGC:toggle, *BGC:state-model*)
HAL:   = HoeheAufLinie         (HAL:interpolate, HAL:log-write)
HAF:   = HoeheAufFlaeche       (HAF:classify-quad)
SetHK: = SetHoehenkote         (SetHK:place-block)
ADS:   = AutoLoadDimStyle      (ADS:load-master, ADS:get-config)

REGELN:
- 2-5 Buchstaben, Grossbuchstaben
- Doppelpunkt als Trenner
- Alle internen Funktionen MUESSEN Prefix haben
- Nur c:Befehle haben KEINEN Prefix
- Globale Variablen: *PREFIX:name*

2. FEHLERBEHANDLUNG (von Lee Mac)

2.1 LOKALE ERROR-HANDLER
------------------------

(defun c:MyCommand ( / *error* old-osmode old-cmdecho)
  
  ;; Lokaler Error-Handler
  (defun *error* (msg)
    ;; ESC und Cancel unterdruecken (DE + EN)
    (if (not (wcmatch (strcase msg) "*ABBRUCH*,*ABGEBROCHEN*,*CANCEL*,*QUIT*,*EXIT*"))
      (princ (strcat "\nFehler: " msg))
    )
    ;; Systemvariablen wiederherstellen
    (if old-osmode (setvar "OSMODE" old-osmode))
    (if old-cmdecho (setvar "CMDECHO" old-cmdecho))
    ;; In Log schreiben
    (MNS:log-write "ERROR" (strcat "Error-Handler: " msg))
    (princ)
  )
  
  ;; Systemvariablen sichern
  (setq old-osmode (getvar "OSMODE"))
  (setq old-cmdecho (getvar "CMDECHO"))
  
  ;; Setzen fuer Command
  (setvar "OSMODE" 0)
  (setvar "CMDECHO" 0)
  
  ; ... DEIN CODE ...
  
  ;; Cleanup (bei normalem Ende)
  (setvar "OSMODE" old-osmode)
  (setvar "CMDECHO" old-cmdecho)
  (princ)
)

WICHTIG:
--------
- *error* lokalisieren (in defun-Parameter)
- System-Variablen IMMER sichern & wiederherstellen
- Cancel-Detection mit wcmatch (DE + EN), NICHT mit member
- Cleanup sowohl bei Erfolg als auch bei Fehler
- IMMER in Log schreiben (siehe Abschnitt 11)


2.2 CANCEL-DETECTION (WCMATCH PATTERN)
--------------------------------------

SCHLECHT - Nur englisch, nur exakte Matches:
--------------------------------------------
(if (not (member msg '("Function cancelled" "quit / exit abort")))
  (princ (strcat "\nFehler: " msg))
)

GUT - Deutsch + Englisch, Pattern-basiert (Lee Mac Stil):
---------------------------------------------------------
(defun MNS:cancel-p (msg)
  ;; Prueft ob User abgebrochen hat (ESC, Cancel, etc.)
  ;; Funktioniert in deutscher UND englischer AutoCAD-Version
  (wcmatch (strcase msg) 
    "*ABBRUCH*,*ABGEBROCHEN*,*CANCEL*,*QUIT*,*EXIT*"
  )
)

;; Verwendung im Error-Handler:
(defun *error* (msg)
  (if (not (MNS:cancel-p msg))
    (princ (strcat "\nFehler: " msg))
  )
  ;; ... Cleanup ...
)


2.3 VL-CATCH-ALL-APPLY FUER ROBUSTE CALLS
------------------------------------------

Fuer Automation/COM Calls oder fehleranfaellige Operationen:

(setq result 
  (vl-catch-all-apply 'vla-copyobjects

(if (vl-catch-all-error-p result)

- Fehler lokal behandeln
- Besser als globaler *error* fuer spezifische Operationen

3. VLA / COM VARIANT HANDLING (CRITICAL!)
================================================================================

3.1 GETTER: VARIANT-EXTRAKTION
------------------------------

PROBLEM:
VLA-Getter wie vla-get-GraphicsWinModelBackgrndColor geben
COM Variants (Typ 19) zurueck, NICHT plain Numbers!

FEHLER:
-------
(setq color (vla-get-GraphicsWinModelBackgrndColor display))
(if (= color 16777215) ...)  ; CRASH: numberp: #<variant 19 16777215>

LOESUNG:
--------
(setq color 
  (vlax-variant-value
    (vlax-variant-change-type 
      (vla-get-GraphicsWinModelBackgrndColor display)
      vlax-vbLong
    )
  )
)

PATTERN (Wiederverwendbar):
--------------------------
(defun MNS:vla-get-color (vla-getter-result / )
  ;; Extrahiert Integer aus VLA COM Variant (Typ 19)
  ;; Getter geben Variants, Setter akzeptieren plain Integers
  (vlax-variant-value
    (vlax-variant-change-type vla-getter-result vlax-vbLong)
  )
)

MERKE:
- VLA GETTER → Variant → muss extrahiert werden
- VLA SETTER → akzeptiert plain Integer direkt
- VLA Farbwerte sind BGR (B*65536 + G*256 + R), NICHT RGB!


3.2 GetCustomByIndex QUIRK
--------------------------

PROBLEM:
vla-GetCustomByIndex gibt manchmal Strings DIREKT zurueck,
manchmal Variants. Abhaengig vom Kontext.

LOESUNG - Safe Variant Value Pattern:
-------------------------------------
(defun MNS:safe-variant-value (val / )
  ;; Sicheres Auslesen: String oder Variant
  ;; Verwendet in: LayerExportImport.lsp (GUID-Lesen)
  (cond
    ((= (type val) 'STR) val)                    ; Bereits String
    ((= (type val) 'VLA-OBJECT) val)             ; VLA Objekt
    ((not (null val))                             ; Variant
      (vl-catch-all-apply 'vlax-variant-value (list val))
    )
    (T nil)
  )
)

4. LAZY-INIT PATTERN (CRITICAL bei DokaCAD!)
================================================================================

4.1 DAS PROBLEM
---------------

Bei Verwendung von DokaCAD (oder anderen Plugins die beim Start
initialisieren) fuehren VLA-Calls, Reactor-Setup oder Dialoge
zur LADEZEIT zu Kollisionen:

SYMPTOME:
- "Ungueltiger Optionstitel" beim Oeffnen
- "Kann nicht zu LISP zurueckkehren"
- Unerwartete Speichern-Dialoge
- AutoCAD-Absturz beim Zeichnungsstart

URSACHE:
- Plugin initialisiert sich
- Dein Script macht gleichzeitig VLA-Calls
- → Konflikt, undefined behavior


4.2 DIE LOESUNG: LAZY-INIT
---------------------------

ALLE VLA-Calls, Reactor-Setup und Dialoge auf den ERSTEN
manuellen Befehlsaufruf verschieben.

PATTERN:
--------
;; Globaler Init-Status
(setq *MNS:initialized* nil)

;; Init-Funktion (wird nur 1x ausgefuehrt)
(defun MNS:ensure-init ( / )
  (if (not *MNS:initialized*)
    (progn
      ;; VLA laden
      (vl-load-com)
      
      ;; Reactor Setup
      (MNS:setup-reactor)
      
      ;; Config laden
      (MNS:load-config)
      
      ;; Notification pruefen
      (MNS:check-notifications)
      
      ;; Fertig
      (setq *MNS:initialized* T)
      (MNS:log-write "INFO" "Initialisierung abgeschlossen")
    )
  )
)

;; In JEDEM c:Befehl als erste Zeile:
(defun c:MyCommand ( / *error* ...)
  (MNS:ensure-init)  ; ← IMMER ERSTE ZEILE!
  ...
)

REGELN:
-------
- KEIN vl-load-com auf Top-Level
- KEIN Reactor-Setup auf Top-Level
- KEINE Dialoge auf Top-Level
- KEIN vla-get-... auf Top-Level
- NUR (princ) auf Top-Level erlaubt
- ALLES andere in ensure-init verschieben

GUID-LESEN BEI STARTUP (Spezialfall):
--------------------------------------
Fuer automatische Checks beim Zeichnungsstart eine
READ-ONLY Variante verwenden die nil zurueckgibt statt
neue Daten zu erzeugen:

(defun MNS:dwg-guid-read ( / )
  ;; Liest GUID, erzeugt KEINE neue wenn nicht vorhanden
  ;; Sicher fuer Startup-Kontext
  ...
  ;; Returns: GUID-String oder nil
)

-----------------------------
(defun calculate-height (p1 h1 p2 h2 pg / vpf vpg scalar)
  ;; Vektor von p1 zu p2
  (setq vpf (list (- (car p2) (car p1)) 
                  (- (cadr p2) (cadr p1))))
  
  ;; Skalarprojektion
  (setq scalar (/ (+ (* (car vpg) (car vpf)) 
                     (* (cadr vpg) (cadr vpf))) 
                  (expt (distance p1 p2) 2)))
  
  scalar
)

REGELN:
-------
- Einrueckung fuer Struktur (2-4 Leerzeichen)
- Kommentare fuer WARUM, nicht WAS
- Leerzeilen fuer logische Bloecke
- Schliessende Klammern kommentieren bei langen Funktionen:

  ) ;end defun
- AutoLISP ignoriert Leerzeichen und Zeilenumbrueche - nutze sie!

7.2 SHARED LIBRARY ARCHITECTURE
--------------------------------

Gemeinsam genutzte Funktionen in eigene Library auslagern.
Verhindert Code-Duplikation ueber Scripts hinweg.

BEISPIEL: BlockImport.lsp
--------------------------
- ObjectDBX Utilities
- Config Management
- Block Import Funktionen
- Verwendet von: SetHoehenkote.lsp, HoeheAufLinie.lsp

LADEN MIT 3-FALLBACK PFADAUFLOESUNG:
-------------------------------------
(defun MNS:load-library (lib-name / path)
  ;; Fallback 1: findfile (AutoCAD Support-Pfade)
  (setq path (findfile lib-name))
  
  ;; Fallback 2: Gleicher Ordner wie Hauptscript
  (if (not path)
    (setq path (findfile 
      (strcat (vl-filename-directory (findfile (strcat *MNS:namespace* ".lsp")))
              "/" lib-name)))
  )
  
  ;; Fallback 3: lib/ Unterordner
  (if (not path)
    (setq path (findfile (strcat "lib/" lib-name)))
  )
  
  ;; Laden oder Fehler
  (if path
    (progn (load path) (MNS:log-write "INFO" (strcat "Library geladen: " lib-name)))
    (progn
      (MNS:log-write "ERROR" (strcat "Library nicht gefunden: " lib-name))
      (alert (strcat "FEHLER: " lib-name " nicht gefunden!"))
    )
  )
)

PROBLEM:
get_tile NACH unload_dialog gibt KEINE Werte zurueck!
Bei verschachtelten Dialogen (Sub-Dialoge) ist der innere
Dialog nach done_dialog WEG.

FALSCH:
-------
(action_tile "ok" "(done_dialog)")
(start_dialog)
(setq name (get_tile "edit_name"))  ; ← ZU SPAET! Dialog ist weg!

RICHTIG:
--------
;; Wert in globale Variable BEVOR Dialog schliesst
(action_tile "ok" 
  "(setq *MNS:temp-name* (get_tile \"edit_name\")) (done_dialog)")
(start_dialog)
;; Jetzt aus globaler Variable lesen
(setq name *MNS:temp-name*)

REGEL:
- action_tile speichert Werte in globale Variablen
- DANN done_dialog
- NACH start_dialog aus globalen Variablen lesen
- Gilt besonders fuer Sub-Dialoge!

11.3 LOGGING (VERPFLICHTEND! AUSFUEHRLICH!)
-------------------------------------------

Jedes Script MUSS ein Log fuehren. Logs muessen AUSFUEHRLICH sein
um Fehler zeitig zu erkennen.

WAS LOGGEN (ALLES!):
- Script-Start mit Version
- Initialisierung (Lazy-Init)
- Config geladen/gespeichert
- Jeden Befehlsaufruf (Start + Ende)
- Jeden wichtigen Schritt im Workflow
- Alle User-Eingaben (Punkte, Werte, Keywords)
- Alle berechneten Ergebnisse
- Alle Datei-Operationen (CSV lesen/schreiben, etc.)
- Warnungen (z.B. fehlende Dateien, Fallback-Pfade)
- Fehler mit vollem Kontext
- VLA-Operationen und deren Ergebnisse
- Abbruch durch User (ESC/Cancel)

LOG-FORMAT:
-----------
[YYYY-MM-DD HH:MM:SS] [LEVEL] Nachricht

LEVEL:
- INFO    = Normaler Ablauf
- WARN    = Unerwartetes, aber nicht kritisch
- ERROR   = Fehler, Funktion abgebrochen
- DEBUG   = Detaillierte Debug-Infos (nur bei *debug-mode*)

[2026-03-17 14:30:22] [INFO]  Befehl HAL gestartet
[2026-03-17 14:30:25] [INFO]  Fixpunkt 1: (1234.567 890.123 0.000) Hoehe: 322.00
[2026-03-17 14:30:28] [INFO]  Fixpunkt 2: (1240.100 895.500 0.000) Hoehe: 344.00
[2026-03-17 14:30:30] [INFO]  Interpolation: Punkt (1237.000 892.500) → 333.12
[2026-03-17 14:30:30] [INFO]  Block gesetzt: HK +333.12 bei (1237.000 892.500)
[2026-03-17 14:30:35] [INFO]  User: ESC → Befehl beendet

----------------
(defun MNS:log-write (level message / appdata log-path fp timestamp)
  ;; Schreibt eine Zeile ins Session-Log
  ;; level: "INFO", "WARN", "ERROR", "DEBUG"
  ;; message: Beliebiger String
  
  ;; Debug nur wenn aktiviert
  (if (and (= level "DEBUG") (not *MNS:debug-mode*))
    (progn) ; Skip
    (progn
      ;; Session-Log-Pfad ermitteln (einmal pro Session)
      (if (not *MNS:log-session-id*)
        (progn
          (setq *MNS:log-session-id*
            (strcat *MNS:appdata-folder* "_"
              (menucmd "M=$(edtime,0,YYYYMMDD_HHMMSS)")
            )
          )
          ;; Log-Rotation beim ersten Schreiben
          (MNS:log-rotate)
        )
      )
      
      (setq appdata (MNS:get-appdata-path))
      (setq log-path (strcat appdata "\\Log\\" *MNS:log-session-id* ".log"))
      
      ;; Timestamp erzeugen
      (setq timestamp (menucmd "M=$(edtime,0,YYYY-MO-DD HH:MM:SS)"))
      
      ;; Schreiben
      (setq fp (open log-path "a"))
      (if fp
        (progn
          (write-line 
            (strcat "[" timestamp "] [" 
              (substr (strcat level "     ") 1 5) ; Padding auf 5 Zeichen
              "] " message)
            fp)
          (close fp)
        )
      )
    )
  )
)


11.4 LOG-ROTATION (MAX 5 SESSIONS!)
-----------------------------------

Nur die letzten 5 Session-Logs behalten.
Aeltere werden beim Start einer neuen Session geloescht.

(defun MNS:log-rotate ( / appdata log-dir pattern files sorted-files delete-count i)
  ;; Loescht alte Logs, behaelt nur die 5 neuesten
  ;; Wird beim ersten log-write der Session aufgerufen
  
  (setq appdata (MNS:get-appdata-path))
  (setq log-dir (strcat appdata "\\Log"))
  (setq pattern (strcat *MNS:appdata-folder* "_*.log"))
  
  ;; Alle Log-Dateien im Log\ Unterordner finden
  (setq files nil)
  (setq f (vl-directory-files log-dir pattern 1))
  (if f (setq files f))
  
  ;; Sortieren (Dateiname enthaelt Timestamp → alphabetisch = chronologisch)
  (setq sorted-files (vl-sort files '<))
  
  ;; Wenn mehr als 4 vorhanden (5. ist die aktuelle, noch nicht erstellt)
  ;; → die aeltesten loeschen
  (setq delete-count (- (length sorted-files) 4))
  (if (> delete-count 0)
    (progn
      (setq i 0)
      (repeat delete-count
        (vl-file-delete (strcat log-dir "\\" (nth i sorted-files)))
        (setq i (1+ i))
      )
    )
  )
)


11.5 CONFIG-MANAGEMENT PATTERN
------------------------------

Persistente Konfiguration ueber Sessions hinweg.
Config-Datei liegt im Config\ Unterordner des AppData-Ordners.

PATTERN: Lesen → Fallback → Dialog → Speichern
----------------------------------------------

(defun MNS:load-config ( / appdata cfg-path fp line)
  ;; 1. Config-Pfad
  (setq appdata (MNS:get-appdata-path))
  (setq cfg-path (strcat appdata "\\Config\\" *MNS:appdata-folder* ".cfg"))
  
  ;; 2. Lesen (falls vorhanden)
  (if (findfile cfg-path)
    (progn
      (setq fp (open cfg-path "r"))
      ;; ... Zeilen lesen ...
      (close fp)
      (MNS:log-write "INFO" (strcat "Config geladen: " cfg-path))
    )
    ;; 3. Fallback: Defaults setzen
    (progn
      (MNS:log-write "WARN" "Keine Config gefunden, verwende Defaults")
      ;; ... Defaults ...
    )
  )
)

(defun MNS:save-config ( / appdata cfg-path fp)
  (setq appdata (MNS:get-appdata-path))
  (setq cfg-path (strcat appdata "\\Config\\" *MNS:appdata-folder* ".cfg"))
  (setq fp (open cfg-path "w"))
  ;; ... Zeilen schreiben ...
  (close fp)
  (MNS:log-write "INFO" (strcat "Config gespeichert: " cfg-path))
)

15.4 ENTMAKEX FUER 3D-ENTITIES
------------------------------

Bei 3D-Objekten mit OCS-Transformation ist command unzuverlaessig.
entmakex schreibt direkt in die Datenbank.

KOORDINATEN-TRANSFORMATION WCS → OCS:
--------------------------------------
;; Normal-Vektor berechnen (Kreuzprodukt)
(setq v1 (mapcar '- p2 p1))
(setq v2 (mapcar '- p3 p1))
(setq normal (list
  (- (* (cadr v1) (caddr v2)) (* (caddr v1) (cadr v2)))
  (- (* (caddr v1) (car v2)) (* (car v1) (caddr v2)))
  (- (* (car v1) (cadr v2)) (* (cadr v1) (car v2)))
))

;; Punkte von WCS nach OCS transformieren
(setq pt-ocs (trans pt-wcs 0 normal))

WANN ENTMAKEX STATT COMMAND:
- 3D-Boegen (ARC) mit verschiedenen Z-Hoehen
- Entities mit OCS-Normal ungleich (0 0 1)
- Wenn exakte DXF-Kontrolle noetig ist
- Wenn command unerwartete Ergebnisse liefert
