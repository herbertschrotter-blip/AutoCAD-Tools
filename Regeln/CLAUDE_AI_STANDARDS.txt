VERPFLICHTENDE STANDARDS (AUTOLISP-SPEZIFISCH)
================================================================================

Bei JEDEM AutoLISP-Code den Claude erstellt oder aendert,
MUESSEN folgende Standards eingehalten werden:

1. CONTEXT-NAMESPACE
   -----------------
   Jede Funktion hat Prefix: MNS:funktionsname
   Jede globale Variable: *MNS:variable*
   Siehe: AutoLISP_BEST_PRACTICES.txt §1.4

2. LAZY-INIT PATTERN
   ------------------
   Kein VLA/Reactor/Dialog auf Top-Level!
   Alles in ensure-init verschieben.
   Erste Zeile in jedem c:Befehl: (MNS:ensure-init)
   Siehe: AutoLISP_BEST_PRACTICES.txt §4

3. APPDATA-ORDNER
   ---------------
   %APPDATA%\AutoCAD\Lisp\<ScriptName>\
   Unterordner: Log\, Config\, Backup\
   Fuer: Log, Config, Backups, CSVs
   NIEMALS in Zeichnungsordner oder Temp!
   Siehe: AutoLISP_BEST_PRACTICES.txt §11.1

4. AUSFUEHRLICHES LOGGING
   -----------------------
   Jede Funktion loggt Start, Ende, Ergebnisse, Fehler.
   Session-basiert, max 5 Sessions, dann rotieren.
   Log-Name: ScriptName_YYYYMMDD_HHMMSS.log
   Siehe: AutoLISP_BEST_PRACTICES.txt §11.3

5. CANCEL-DETECTION
   -----------------
   wcmatch mit DE+EN Pattern, NICHT member.
   "*ABBRUCH*,*ABGEBROCHEN*,*CANCEL*,*QUIT*,*EXIT*"
   Siehe: AutoLISP_BEST_PRACTICES.txt §2.2

6. ERROR-HANDLER
   --------------
   Lokaler *error* in jedem c:Befehl.
   Systemvariablen sichern + wiederherstellen.
   Fehler ins Log schreiben.
   Siehe: AutoLISP_BEST_PRACTICES.txt §2.1

7. VLA VARIANT HANDLING
   ---------------------
   Getter: vlax-variant-change-type → vlax-vbLong → vlax-variant-value
   Setter: plain Integer
   BGR Farbreihenfolge (nicht RGB!)
   Siehe: AutoLISP_BEST_PRACTICES.txt §3

8. PERSISTENTE CONFIG
   -------------------
   Pattern: Lesen → Fallback → Dialog → Speichern
   In %APPDATA%\AutoCAD\Lisp\<ScriptName>\Config\<ScriptName>.cfg
   Siehe: AutoLISP_BEST_PRACTICES.txt §11.5

9. README PFLICHT
   ---------------
   docs/ScriptName_README.md
   Mit: Befehle, Config, Log, Namespace, Tech Details
   Siehe: Lisp_Readme_Rules.txt

10. SHARED LIBRARIES
    ----------------
    Gemeinsamer Code in eigene .lsp auslagern.
    3-Fallback Pfadaufloesung.
    Siehe: AutoLISP_BEST_PRACTICES.txt §7.2

SICHERHEIT EXPLIZIT ANSPRECHEN
================================================================================

AUTOLISP SECURITY CHECKLIST:
-----------------------------
- Input-Validierung (Punkte, Zahlen, Strings)
- VLA-Calls mit vl-catch-all-apply absichern
- Selection Sets freigeben (Memory Leak!)
- Keine gefaehrlichen Operationen (erase all, purge all)
- Keine hardcodierten Pfade
- Keine Passwoerter/API-Keys im Code
- findfile vor jedem load

UNIVERSAL:
----------
- Code-Injection Risiken pruefen
- SQL-Injection (falls Datenbank)
- Path-Traversal (../ Attacken)
- Hardcoded Secrets vermeiden
